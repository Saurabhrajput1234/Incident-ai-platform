# Incident AI Platform — Phase 1 & 2 Documentation

## Overview

AI-powered incident management platform built with FastAPI, PostgreSQL, SQLAlchemy, and Alembic.

## Phase 1 — Foundation

### Dependencies (pyproject.toml)

| Package | Version | Purpose |
|---|---|---|
| fastapi | 0.109.0 | Web framework |
| uvicorn[standard] | 0.27.0 | ASGI server |
| pydantic-settings | 2.1.0 | Settings management |
| python-dotenv | 1.0.0 | .env file loading |

### Setup

```bash
# Create virtual environment
python -m venv venv

# Activate (Windows)
venv\Scripts\activate

# Install dependencies
pip install -e .

# Copy env file
copy .env.example .env

# Run server
uvicorn app.main:app --reload
```

### Configuration (app/core/config/__init__.py)

Settings are loaded via `pydantic-settings` from the `.env` file.

| Variable | Default | Description |
|---|---|---|
| APP_NAME | Incident AI Platform | Application name |
| APP_VERSION | 0.1.0 | Version |
| ENVIRONMENT | development | Environment name |
| DEBUG | true | Debug mode |
| API_V1_PREFIX | /v1 | API version prefix |
| ALLOWED_ORIGINS | [...] | CORS allowed origins (JSON array) |
| LOG_LEVEL | INFO | Logging level |
| DATABASE_URL | postgresql+asyncpg://... | PostgreSQL connection string |

> Note: `ALLOWED_ORIGINS` must be a JSON array in .env:
> ```
> ALLOWED_ORIGINS=["http://localhost:3000","http://localhost:8000"]
> ```

### Logging (app/core/logging.py)

Configured via `LOG_LEVEL` setting. Outputs to stdout with format:
```
YYYY-MM-DD HH:MM:SS - name - LEVEL - message
```

### CORS Middleware (app/main.py)

Configured to allow requests from `ALLOWED_ORIGINS`. Supports all methods and headers with credentials.

### Exception Handlers (app/core/exceptions.py)

| Exception | Status Code | Response |
|---|---|---|
| HTTPException | varies | `{detail, status_code}` |
| RequestValidationError | 422 | `{detail: [...errors], status_code}` |
| Exception (generic) | 500 | `{detail: "Internal server error", status_code}` |

### API Versioning

All routes are prefixed with `/v1` set via `API_V1_PREFIX` in settings. Routes are registered in `app/api/router.py`.

### Health Endpoints

| Method | URL | Description |
|---|---|---|
| GET | /v1/health | App health check |
| GET | /v1/db-health | Database connectivity check |

#### GET /v1/health
```json
{"status": "healthy"}
```

#### GET /v1/db-health — Success
```json
{"status": "healthy", "database": "connected"}
```

#### GET /v1/db-health — Failure
```json
{"status": "unhealthy", "database": "disconnected", "error": "..."}
```

Auto-generated by FastAPI:

## Phase 2 — Database Foundation

### Additional Dependencies

| Package | Version | Purpose |
|---|---|---|
| sqlalchemy | 2.0.25 | ORM + async engine |
| asyncpg | 0.29.0 | Async PostgreSQL driver |
| alembic | 1.13.1 | Database migrations |

### Database Setup

1. Install PostgreSQL and create the database in pgAdmin or psql:
```sql
CREATE DATABASE incident_ai;
```

2. Update `.env` with your credentials:
```
DATABASE_URL=postgresql+asyncpg://postgres:yourpassword@localhost:5432/incident_ai
```

> If your password contains special characters, URL-encode them:
> - `@` → `%40`
> - `#` → `%23`

### SQLAlchemy Base (app/database/postgres/base.py)

Provides the `Base` class that all future models will inherit from:
```python
from app.database.postgres.base import Base
```

### Async Session (app/database/postgres/session.py)

- Creates an async SQLAlchemy engine from `DATABASE_URL`
- Provides `get_db()` — a FastAPI dependency that yields an `AsyncSession`
- Sessions are auto-closed after each request

Usage in an endpoint:
```python
from app.database.postgres.session import get_db
from sqlalchemy.ext.asyncio import AsyncSession
from fastapi import Depends

@router.get("/example")
async def example(db: AsyncSession = Depends(get_db)):
    result = await db.execute(...)
```

### Alembic Migrations

Initialize and run migrations:

```bash
# Auto-generate migration from models
alembic revision --autogenerate -m "description"

# Apply migrations
alembic upgrade head

# Rollback one step
alembic downgrade -1

# View history
alembic history
```

Alembic reads `DATABASE_URL` from settings — no separate config needed.
